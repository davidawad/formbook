## Shared-model requests (for fb-595.54.82)

1. **A sans-serif face: Arial / Liberation Sans in LaTeX.**
   - Folders: all eight doc types.
   - Evidence: Fla. R. App. P. 9.045(b) allows only Arial 14 or Bookman Old Style 14 for computer-generated documents
     (rules.md FLADISTCTAPP3-FORM-003); the templates set Liberation Sans, Arial's metric twin. `fb engines gen
     .../motion-brief` fails: "no LaTeX face for `Liberation Sans` (one face per template: newtx, tgschola,
     ebgaramond, gelasio)" (tools/fb/src/enginegen/gen.rs `latex_face`). Needed: a face line for "Liberation Sans" /
     "Arial" (TeX Gyre Heros or helvet share Arial's advances, which Arial took from Helvetica; measure the bias and
     the ellipsis advance as for newtx), and Liberation Sans in `list_width` (lib/docx/xdoc.lua) for tables of
     authorities.
2. **Word counts the template computes.**
   - Folders: amicus-brief, answering-brief, opening-brief, petition-for-discretionary-review,
     petition-for-review, petition-for-writ, reply-brief.
   - Evidence: each template's certificate of compliance (FLADISTCTAPP3-CERT-001, -CERT-003; Rule 9.045(e)) states
     the brief's word count, which the template counts from the body (`count-words`). The INPUTs carry no count
     field, and the checklist allows no new frontmatter fields. So the certificate cannot be expressed as layout
     blocks, and moving these templates onto xdoc now would drop the count from a mandated certificate.
     Needed: a `{words}` value the model counts in all three engines, by the 9.045(e) exclusions: the body up to the
     tail, headings, notes and quotations included.
3. **Space that fills the page (typst `v(1fr)`) on a cover.**
   - Folders: the same seven.
   - Evidence: the cover centers the brief title between the caption and the counsel block with `v(1fr)` above and
     below it, and puts counsel at the foot of the page. Fixed `above` values would put counsel at a different height
     for every caption length.
4. **An empty item of a list field kept as an empty line.**
   - Folders: motion-brief (and any INPUT whose `signature.lines` holds `""` to separate two counsel).
   - Evidence: motion-brief INPUT `signature.lines` has `""` between the two co-counsel. The old template printed an
     empty line there. In xdoc.typ an empty paragraph has no height, so the two counsel now run together (page 4).
     LaTeX and Word would set an empty paragraph a line high, so the model has to choose one behavior for all three
     engines.
5. **A list item by index (`{signature.lines.0}`) or a slice.**
   - Folders: all eight.
   - Evidence: the certificates of service were signed with "/s/ signer" plus the first two signature lines (name,
     bar number). `lookup` reads no array index, so the motion-brief certificate is now signed "/s/ {signature.signer}"
     only. That is still a signature under Rule 2.515 (FLADISTCTAPP3-SIG-001); this is tier 2.

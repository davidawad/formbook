# fb-595.54.11.4: when no line of a note fits on its mark's page

The question (from fb-595.54.11 a3, finding 3): LibreOffice moved the mark's line to the next page when no line of
its note fitted (kentucky eastern-district motion-brief p4, notes 3-4), typst kept the line and moved the note whole;
ca10 reply-brief sample 2 p8 went the other way (LibreOffice kept the line and moved note 2 whole). This file is the
design the bead asks for (the bead store is not in the pod that did the work), the evidence behind it, and what was
implemented. Measured 2026-10-29 on master 0d114b2d8 with typst 0.15.0 and the repo's LibreOffice.

## 1. What decides it

**LibreOffice** keeps a note whole (Footnote Text has `keepLines`, fb-595.54.11.2/3), so "no line fits" is "the
whole note does not fit". It then does one of two things, decided by **whether the page already holds a note**:

- no note on the page yet: the mark's line moves on with its note (kentucky p4: notes 3 and 4 are its first notes);
- a note already stands on the page: the line stays and the note moves whole to the next page (ca10 sample 2 p8:
  note 1 is on p8, note 2 goes to p9 while "information.2" stays on p8).

So `keepLines` alone does not explain ca10. It only makes "no line fits" happen whenever the whole note does not fit.
The earlier note is the switch. Evidence: a synthetic sweep in the ca10 reply-brief folder (a paragraph with a 5-line
note, shifted down the page word by word, with and without a one-line note in the paragraph before it):

| earlier note on the page | filler words | docx: mark's line / its note |
| --- | --- | --- |
| no | 83-119 | both p6 (the line moved on) |
| yes | 67-121 | line p5, note p6 (the note moved whole) |

The same sweep in the kentucky folder (typst, latex and docx) gives typst and LaTeX moving the line in both rows,
and docx keeping it only in the "yes" row (filler 452-468: typst 4/4, latex 4/4, docx 3/4 as mark/note page).

**typst** with a bare paragraph moves the line on with its note, as LaTeX does, with or without an earlier note
(the kentucky sweep). It keeps the line and moves the note whole only inside a block. Examples: a block-wrapped
paragraph or list item (Md. Ct. App. petition-for-writ notes 60, 61, 150, 154) and a quotation (W. Va. Supreme Court
brief-on-the-merits note 3, eval.yaml). There a note cannot take its line along (fb-595.54.11.1).

**Kentucky p4 today:** typst, latex and docx all set the line "(citing such cases). Both appellate courts3 and trial
courts4" on p5 with notes 3 and 4. The difference the a3 finding saw is gone on master.

## 2. Two typst faults found on the way: a note before its mark

xengine.typ promises that a note never starts on a page before its mark (fb-595.54.11.1). That held only for a
paragraph wrapped in a block that holds nothing but the paragraph. A probe of every typst render (1263 samples:
query each `footnote.entry`'s page against its mark's) and the synthetic sweeps found two more cases:

1. **A bare paragraph under typst's widow and orphan cost.** typst places the note of the line it lays. When the next
   line then does not fit, the cost keeps the two together: both lines move on and the note stays behind. Seen in
   ca10 (14 pt type, 31.4 pt lines, 20 pt notes) with a mark on a paragraph's second-to-last line, and reproduced
   in plain typst without xengine. With a cost of 0 % it never happens. No committed render hits it today.
2. **A list item of the shared model** (lib/typst/xdoc.typ `list-items`: `block(pad(left: ..., par(...)))`).
   unwrap-note-par did not look inside the `pad`. On master, a fresh render of the Md. Ct. App.
   petition-for-writ sets note 147 on p55 and its mark on p56.

## 3. Design

**The rule the model keeps:** the bare-typst and LaTeX rule. A note starts on its mark's page. When none of it fits
there, the mark's line moves on with it. typst is the reference and LaTeX already agrees, so this changes no gated
render. LibreOffice departs from it in one case only: a page that already holds a note. That stays a docx
difference (below).

**What xengine.typ owns** (lib/typst/xengine.typ, header and the two rules):

- `unwrap-note-par` (fb-595.54.11.1): a block that only wraps a paragraph is laid out as the bare paragraph once one
  of its notes started on a page before its mark. It now also looks through a `pad` that indents only on the left
  (xdoc list items). The bare paragraph adds the pad to its first-line and hanging indents, so the lines stay where
  they were.
- `loosen-note-par` (new): a paragraph whose note started on a page before its mark is laid out without the widow
  and orphan cost. Its mark's line stays with the note, and the line after it moves on alone. Word sets a paragraph
  that anchors a note the same way (Body Text Note: no widow control), and so does LaTeX where its filter turns widow
  control off for such a paragraph. `<xe-loose>` holds the change, so the layout converges, the same way `<xe-bare>`
  holds `unwrap-note-par`. The notes keep their own cost (fb-595.54.11.3): a note's entry takes its mark's styles,
  not the paragraph's show rule. typst has already shown a paragraph's footnotes by the time the paragraph is shown,
  so the rule looks only at a paragraph that holds an element tag, and queries for the notes between its start and
  end markers.
- Both rules act only after a note has been set before its mark. A paragraph whose notes start on their marks' pages
  is laid out exactly as before.

**Risk to gated folders, measured:** every typst sample (1263, all folders with `typst/main.typ`) was compiled before
and after the change with the same flags. 1261 are byte-identical. The two that differ:

- `courts/ninth-circuit/alaska/state/supreme-court/motion-brief` (cross_engine: report). In an intermediate layout
  pass, note 62's list item had its note before its mark, so the item is now laid out bare. Its line "inundated her
  home, ... flooding.62" moves to p17 with note 62, which is where the LaTeX render already sets it (before: line
  on p16, note deferred to p17). Re-rendered, `check.sh` typst 10 passed 0 failed, committed.
- `courts/fourth-circuit/maryland/state/court-of-appeals/petition-for-writ` (cross_engine: report): note 147 now
  starts on p56 with its mark. Not re-rendered here: its committed typst PDF predates master's library, and a fresh
  render fails DEF-FORM-002 (text in the margin) on master's xengine.typ as well as on this one (follow-up below).

**Rejected:** (DECIDED, reasons given)

- Making typst follow LibreOffice (keep the line and defer the whole note when the page already holds a note).
  typst has no knob for it on a bare paragraph. Doing it would mean separating the mark from its entry, or wrapping
  the paragraph in a block on purpose, which brings back the note-before-mark fault. LaTeX would have to change too,
  or it would part from typst on every such page. That risk falls on every gated folder with two notes on a page,
  for a gain only to the docx engine.
- Extending `unwrap-note-par` to a note deferred past its mark (a block's note on a later page than the line). Tried:
  the Md. Ct. App. petition-for-writ render then does not converge ("document did not converge within five
  attempts", which fails the render). It also moves Puerto Rico petition-for-rehearing and Ohio Ct. App.
  amicus-brief. A quotation (W. Va. note 3) is in any case a block with its own spacing and a right indent, which no
  bare paragraph reproduces.

**Docx difference that stays:** on a page that already holds a note, LibreOffice keeps the mark's line and moves a
note that does not fit whole to the next page, where typst and LaTeX move the line. Word's styles offer no setting
for this. A docx render that meets it stays reported where the folder already records it (ca10 reply-brief sample 2:
its README, no eval.yaml gate, fb-595.54.5).

# DOCX: what works, what does not

The docx engine (see `docs/EVAL-LOOP.md`, "Engines") is built with pandoc, a per-court `docx/reference.docx`, and Lua filters in `docx/*.lua`. Gates 0 and 1 run on the **LibreOffice PDF** of the `.docx` (`<id>.docx.pdf`, made by `soffice --headless --convert-to pdf`), because there is no scriptable Word here. Word may paginate slightly differently (line breaking, font metrics, table row heights). The `.docx` must also open in Word and in LibreOffice without a repair prompt.

A court PR may deliver docx as BLOCKED or partial if it lists the exact failing check IDs and why. Silently missing is not acceptable. Use this file for the limits that recur across courts; add to it when you meet a new one (one line: the thing, the engine behavior, the workaround or the BLOCKED reason).

## Use the Word-native feature when one exists

| Court wants | Word-native feature | Notes |
|---|---|---|
| Numbered lines in the margin (pleading paper) | Section line numbering, `w:lnNumType` (`w:countBy`, `w:restart="newPage"`, `w:distance`) in `w:sectPr` | Numbers only the lines in the body flow; a table, a text box or a footnote is not numbered. Exactly 28 numbered lines per page needs exact line spacing (`w:spacing w:line=".." w:lineRule="exact"`), not "double". |
| Vertical rules beside the text (pleading paper) | Page borders (`w:pgBorders`), left and right | Border offset is measured from text or from page edge (`w:offsetFrom`); LibreOffice and Word differ on a double rule's spacing. |
| Table of contents | TOC field (`TOC \o "1-5" \h`) over heading styles | Fields are empty until updated. Word asks to update on open if `w:updateFields` is set in `settings.xml`; LibreOffice needs an update on load. For the checked PDF the renderer must have the TOC populated, so generate it (a filter that writes the entries and page numbers from a first pass, or a LibreOffice macro update step in `docx/render.sh`). |
| Table of authorities | TA fields on each citation and a `TOA` field per category | Same update caveat. LibreOffice does not honor TA/TOA fields the way Word does (it has its own bibliography/index model): expect BLOCKED on the TOA check IDs unless the filter writes the table text itself, with page numbers from a first pass. |
| Headings stay with the next paragraph | `w:keepNext` on the heading styles | Works in both. Also set `w:keepLines` for headings. |
| Widows and orphans | `w:widowControl` | Works in both. |
| Page numbering in the footer | `PAGE` field, section `w:pgNumType` for roman then arabic | Works in both. A "Page X of Y" form needs `NUMPAGES`; check it in the PDF. |
| Footnotes | Native footnotes (pandoc emits them) | Footnote text size comes from the `Footnote Text` style in the reference.docx. |
| Block quotations, indentation | Paragraph styles with `w:ind`, not tabs or spaces | |
| Fonts | Name the font in the styles; the court font must be installed on the machine that opens the file | Word will substitute silently if the font is missing. Embedding (`w:embedTrueTypeFonts`) works in Word but LibreOffice ignores it. The checked PDF must show the declared font; the font name check is the proof. For the PDF conversion the vendored fonts must be visible to LibreOffice (install them for the user running the check, or point `docx/render.sh` at a font directory). |

## Pleading paper: why typst is the reference engine

Pleading paper (California, N.D. Cal. and other courts that ask for numbered lines: a fixed grid of 28 numbered lines per page, a double rule at the left of the text and a single rule at the right) is a page layout, not a text feature. Typst draws it directly: the numbers and rules are page furniture, and the body is set on the grid. Word has no pleading-paper layout of its own, and every way to build one in a modern `.docx` is a workaround:

- **Line numbering** (`w:lnNumType`) numbers the lines of body text, not the page's grid. Tables, text boxes and footnotes are skipped, a single-spaced block (counsel, caption, signature, quotations) puts two text lines on one grid line, and a heading with space before it shifts every number below it. The numbers stop lining up with the 28 positions the court's paper has.
- **Numbers in a page-anchored text box** (a VML box in the header or footer holding 1 to 28, the approach in `courts/ninth-circuit/california/federal/northern-district/motion-brief/docx/cand.lua`) keeps the grid, but the text is not tied to it: whether a body line sits on its number depends on exact line heights, and Word and LibreOffice place text boxes, page borders and double rules differently.
- **Page borders or bar tabs** for the rules draw at offsets that differ between Word and LibreOffice (see the table above).

So a pleading-paper DOCX can pass the mechanical gates on the LibreOffice PDF and still look wrong in Word, or drift after the user edits it. Treat DOCX output for these courts as best effort: a starting point to edit, not a file to sign. Where the docx cannot meet a pleading rule, the folder marks it `BLOCKED: <check ID>: <why>` and the README says so; nobody should spend time forcing Word to match typst line for line. Typst stays the reference: it is the engine the templates are written in, reviewed in, and the one an attorney's review (`skills/formbook-review/SKILL.md`) judges.

## Known limits

- **Pagination differs by renderer.** Word and LibreOffice disagree on line breaks and therefore on page numbers in a TOC or TOA. A TOC/TOA page-number check passes against the LibreOffice PDF and may be off by a page in Word. State this in the PR; do not "fix" it by forcing page breaks.
- **Exact page counts and word counts** are measured on the LibreOffice PDF.
- **Fields (TOC, TOA, cross-references)** are computed by the application. pandoc writes the field but not its result. A docx whose fields were never updated looks empty in a viewer that does not update on open. Prefer writing the result text into the field (cached field result) so every viewer shows it.
- **PDF bookmarks and tagged PDF** are not emitted by the LibreOffice conversion by default; a check for them is an engine-specific check (`engines: [typst, latex]` with a reason) unless `docx/render.sh` enables them (`--convert-to 'pdf:writer_pdf_Export:{"ExportBookmarks":{"type":"boolean","value":"true"}}'`).
- **Cover pages and caption boxes** (case caption tables with a vertical rule) are tables in Word. Table borders render slightly differently between Word and LibreOffice; judge the LibreOffice PDF and say so.
- **Line numbering with tables or footnotes**: Word skips them; some courts' pleading rules require numbers to continue. Mark such a requirement BLOCKED with its check ID if no workaround (a frame or text box per page) is acceptable.
- **Kerning, ligatures and hyphenation** are application defaults; the typst and latex engines control them. Do not assert them for docx.
- **Image-only content** (a scanned exhibit) cannot pass the content gate; exhibits are out of scope for the templates.

## Checking a docx

1. `sh tools/render.sh --engine docx <doc-dir> usage/INPUT-<id>.md` writes `usage/OUTPUT-<id>.docx` and `usage/OUTPUT-<id>.docx.pdf`.
2. `sh tools/check.sh <doc-dir> --engine docx` runs Gates 0 to 3 on the `.docx.pdf` and writes `usage/.check-docx.txt` only when everything passes.
3. Open the `.docx` in LibreOffice (and Word if you have it) and confirm there is no repair prompt. Record that, and every page you looked at, in the review file under `## sample <id> docx`.
4. Anything that cannot pass goes in the PR as `BLOCKED: <check ID>: <why>` lines.

## Lessons from ca9 (fb-595.43)

- **Dot leaders**: a Word dot-leader tab comes out of the LibreOffice PDF as contiguous dots ("....."), not the spaced " . . ." typst and latex draw; `tools/check/leader-entries.awk` reads both.
- **Page-number column**: give contents/authorities rows a right indent (the number column) and put the right tab beyond it, inside the margin; LibreOffice honours a tab past the right indent for Word documents, so a long title wraps before the numbers instead of pushing them to the next line.
- **Footer first**: LibreOffice draws the footer before the body, so the page number is the first run of a page in `pdftohtml` order; the checker's "page N starts with" (`first_run`) takes the topmost run above the footer.
- **Reproducible output**: `fb render` re-runs on every check, so the docx must be byte-reproducible for a Gate 2 review to stay current. `fb render` writes the archive of a multi-pass build with fixed part dates and a fixed order (tools/fb/src/docxpass.rs); `fb render` rewrites LibreOffice's wall-clock `/CreationDate`, `/ID` and `/DocChecksum` (tools/fb/src/pdfrepro.rs).
- **Small capitals**: LibreOffice synthesizes them at about 80 % size; under a 14 pt minimum use bold or full capitals instead.
- **Check boxes**: a bordered run (`w:bdr`) holding "X" or non-breaking spaces needs no symbol font, so no fallback face appears in the PDF.
- **Page numbers without shell**: a filter that writes needles to `$FORMBOOK_NEEDLES` gets `fb render`'s multi-pass build (tools/fb/src/docxpass.rs and docxpages.rs; contract in their module docs): pages looked up in the LibreOffice PDF, fed back through `$FORMBOOK_PAGES` until they settle, footers `rIdFtrNone`/`rIdFtrPage`/`rIdFtrAdd` added, the last sectPr taken from `$FORMBOOK_FINAL`. ca9 uses it; no `docx/render.sh` is needed.
- **Reference document from text**: a court keeps its Word styles as `docx/reference.xml` instead of a binary `docx/reference.docx` and a shell builder. `fb render` starts from pandoc's default reference (or the cross-engine recipe, `base="xengine"`) and applies it (tools/fb/src/docxref.rs: `w:docDefaults`, `w:style` merged by id or `styles="replace"`, a verbatim `w:styles` part, `<footer id="rId..">` parts, `<part>`, the last `w:sectPr`, `theme-font`, `strip-theme-fonts`, `{font}` for the typst face; see "The docx template without shell" below), in a staged copy of `docx/` so a court's `docx/render.sh` finds `reference.docx` beside itself. `fb docx-reference <docx-dir> <out.docx>` writes the same file for opening the styles in Word. A folder keeps one of the two, never both.

## The docx template without shell (fb-595.68)

A folder on the shared document model (docs/EVAL-LOOP.md, "Generated engines"; fb-595.54.12) does not write these by hand: `fb engines gen` writes its `docx/reference.xml` and a one-line `docx/xdoc.lua` (`require("docx.xdoc")`, lib/docx/xdoc.lua) from its `typst/layout.yaml`; change the layout and generate again.

A court's docx folder holds declarative inputs only: `reference.xml` (the Word styles), `*.lua` filters (pandoc runs every top-level `docx/*.lua`, in name order; a module a filter loads with `dofile` goes in a subfolder, such as `docx/lib/`), and nothing else that runs. `fb render` (Rust) builds `reference.docx`, runs the pandoc passes, measures the pages, writes the footers and the last section and packs the archive. No `docx/*.sh`, no committed binary `reference.docx`, no `.shell-safety-baseline.json` entry under `courts/`.

**`docx/reference.xml`** (tools/fb/src/docxref.rs; the grammar is in its module doc):

- `{font}`, anywhere in the file, is the body face of the folder's typst template (tools/fb/src/typstface.rs: its `set text(font: ..)`, or the `#let font-family` binding). Name the face only through `{font}`, so the docx can never set another face than typst; `fb lint fonts` reports a docx that does (below).
- `base="xengine" size=".." body=".." single=".." [indent list heading heading-before heading-after quote note-after note note-size footer]`: the styles of the cross-engine recipe (tools/fb/src/docxxengine.rs, the Rust port of `lib/docx/xengine-reference.sh`, byte-identical output) in the typst face; `<w:style>` and `<w:docDefaults>` children then replace or add styles on top of it (`styles="merge"`, the default), and a `<footer id="rIdFooter1">` replaces the recipe's page-number footer (the CIT complaint). ca9 (`courts/ninth-circuit/court-of-appeals/docx/reference.xml`) is the recipe alone; the SCOTUS cert petition adds its own styles and the `w14` namespace (`xmlns:*` and `mc:Ignorable` on `<reference>` go onto the styles part).
- `<w:styles ..>..</w:styles>`: the whole styles part, verbatim (what `fb docx-reference --extract` writes). `<part name="word/settings.xml">..</part>` replaces another part of pandoc's reference. `<footer id="..">`, `<header id="..">`, `<w:sectPr>` and `theme-font` as before.
- `pandoc-from="markdown-smart"`: the reader of every pass, for a template whose `render.sh` only changed pandoc's options (the Texas CCA petition).

**`fb render`'s passes** (tools/fb/src/docxpass.rs, docxpages.rs): a filter that writes needles to `$FORMBOOK_NEEDLES` gets pages back in `$FORMBOOK_PAGES` until they settle; its sections name the footers it lists in `$FORMBOOK_FOOTERS` (or fb's `rIdFtrNone`, `rIdFtrPage`, `rIdFtrAdd`) and the headers it lists in `$FORMBOOK_HEADERS` (the same format: `ID <TAB> paragraphs`, one per line; the W.D. Wash. pleading paper); the last section is `$FORMBOOK_FINAL`. A filter never names a footer or header of `reference.xml` (nor the recipe's `rIdFooter1`, nor a numbered `rIdN`): pandoc may renumber those relationships, and the section then dangles (fb-595.64). `fb lint docx` and `fb lint <doc-dir>` reject it (`docx-rid`, tools/fb/src/lint/docxrid.rs; fb-595.70), and a footer or header that `reference.xml` declares under a numbered id. `$FORMBOOK_STATE` is a file kept across the passes of one render (empty before the first), for a decision a pass takes from the pages that later passes must keep: the Fourth Circuit briefs (`courts/fourth-circuit/court-of-appeals/*/docx/ca4.lua`) list there the headings a pass left at the foot of a page, which open the next page from then on (typst's sticky headings; were `docx/render.sh` and `pagemap.awk`). `$FORMBOOK_META` is the sample's frontmatter as JSON (`pandoc.json.decode(.., false)`), the strings as written, for a filter that builds text the way a jq or shell step did. A filter may also replace the document: read `PANDOC_STATE.input_files[1]`, build markdown, and `pandoc.read(md, "markdown+smart", PANDOC_READER_OPTIONS)` gives the AST pandoc would have read from a file a script wrote (the BAP 8th Cir. opening brief, `docx/lib/front.lua`).

### Porting checklist (one folder; fb-595.68 step 2)

The port is complete only when the DOCX path uses declarative `reference.xml` and Lua filters, its face resolves through `{font}` to the typst template's declared face, every old builder/render shell script and script-only artifact is removed, and the court has no remaining entries in `.shell-safety-baseline.json`. If the folder has LaTeX, adopt and gate it alongside DOCX; do not set cross-engine gating until every engine present passes tier 1 (including `DEF-COVER-001` and `DEF-TOC-001`, each with zero failures) and matches typst on every page and line. Record any engine that cannot match by folder, engine, failing XENG IDs, and the specific page or line; leave that engine at `report`.

For a multi-folder port, apply every step independently to every assigned folder. A fan-out is complete only when each folder has zero entries in `.shell-safety-baseline.json`, no per-court DOCX shell builder or private script-only artifacts, a `{font}` reference that resolves to its typst face, and passing tier-1 and cross-engine checks for every engine present. Report exceptions by folder and engine with the exact failed check IDs and page or line; do not count an exception as adopted.

For a fan-out tracked by a bead, apply this checklist to every named folder. The end state is declarative: only `reference.xml` and Lua filters remain in `docx/`; the Word face comes from the typst template through `{font}`; and the folder has no entry in `.shell-safety-baseline.json`. A script that cannot be represented by `fb render`'s declarative inputs and Lua passes is a recorded blocker, not a reason to retain a per-court shell script.

1. Render the folder on the current tree first and keep the outputs: `fb render --engine docx <dir> usage/INPUT-<id>.md /tmp/base/<id>.docx.pdf` for every INPUT (the committed OUTPUTs of older folders may be stale; compare with this render, not with them).
2. Styles. If the builder is `lib/docx/xengine-reference.sh` alone, write `<reference .. base="xengine" ..>` with its arguments (`font=` is dropped: the face is `{font}`). Otherwise run `fb docx-reference --extract <dir>/docx`: it writes `docx/reference.xml` from the committed `reference.docx` (styles verbatim, footers, headers, the last section, the theme face, any other changed part; the typst face as `{font}`), rebuilds it and prints `same` or `DIFFERS` per part (exit 1 on a difference). Replace its header comment with the builder's description (rule numbers, pitches in twips). A reference built by `make-reference.sh` or `build-reference.sh` is handled the same way: extract its committed `reference.docx`, then remove the builder.
3. Face. Set `{font}` to the face declared by the typst template in every folder, including folders whose old builder used another face (such as EB Garamond). A docx face mismatch is a defect, not an accepted porting difference; re-render and run every gate after correcting it.
4. `docx/render.sh`, by what it does:
   - only pandoc options (`--from markdown-smart`): `pandoc-from` on `<reference>`;
   - page numbers from a first pass (a page map, `pagemap.awk`, a measure loop): write needles instead (ca9 `docx/ca9.lua`, ca7 `opening-brief/docx/ca7-opening-brief.lua`): an id per heading and citation in document order, `B` in the body and `N` in a footnote, the text and the words after it (a `B` needle that runs over a page end, with the footnotes between its halves, is found by its head on the page and its tail at the top of the next, as the ca8 `pagemap.awk` did); `#section` lines saying where lower roman and arabic start; the same placeholder on the first pass as the script used, so the second pass matches;
   - a script that searched headings only on body pages, at the start of a line: fb searches the whole text in order, so put a needle first that moves the search past the contents (the authorities' heading with its first group, ca5; the contents' last row by title and page, PTAB: `pdftotext` sets a contents row's label apart from its title), and give each heading the words after it, a following heading's label included (a bare "Argument" falls back to "Summary of Argument");
   - footers and the last section written by the script: list the footer paragraphs in `$FORMBOOK_FOOTERS` under the ids the sections name (headers in `$FORMBOOK_HEADERS`; never a footer id of the reference document), and write the last `w:sectPr` to `$FORMBOOK_FINAL`;
   - text built by jq, awk or perl (cover, certificates, word count): port it to Lua on `$FORMBOOK_META` and the sample text, rule for rule (bap8 `docx/lib/front.lua`), and build the document from the same markdown the script fed pandoc;
   - zip, dedupe, validate: nothing; `fb render` does it.
5. Convert the builder and helpers into declarative inputs or Lua filter code, then delete every per-court `docx/*.sh` (`render.sh`, `make-reference.sh`, and `build-reference.sh`), `reference.docx`, and helpers only they used (`*.awk`, `*.jq`, `footer.xml`, `parts/`). Keep rule-specific values in `reference.xml`; declare its body face only as `{font}`, resolved from the typst template. Remove the folder's keys from `.shell-safety-baseline.json`; after the port, court-specific DOCX shell baseline entries must be zero. For a fan-out, confirm the baseline has zero entries for all assigned folders.
6. Render again and compare with step 1: `cmp` the `.docx.pdf` (and `.docx`); if bytes differ, `pdftoppm -r 100` both and compare every page (`magick compare -metric AE` must print 0). The `.docx` may differ in package plumbing only (footer part names, unused fb footers, whitespace between appended styles).
7. Run `sh tools/check.sh <dir> --engine <engine>` for every engine present (zero failed tier-1 checks, including `DEF-COVER-001` and `DEF-TOC-001` where applicable); compare all latex/docx INPUTs to typst and gate only when XENG-001..003 pass on each. Re-do Gate 2 on every page of each new render, run `sh tools/check-selftest.sh <dir>`, ensure `fb lint fonts` does not report the folder, and run `cargo test -p fb`.

**`fb lint fonts`** reports every docx folder whose styles name a face other than its typst template's (tools/fb/src/lint/docxfonts.rs); `fb lint fonts --docx-strict`, which `just lint` runs, fails on them and on a `reference.docx` it cannot read (fb-595.68.39).

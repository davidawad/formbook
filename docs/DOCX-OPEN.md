# DEF-DOCX-OPEN: every delivered .docx opens

The `.docx` an engine delivers must open in Word and in LibreOffice without a repair prompt (`docs/DOCX.md`).

DEF-DOCX-OPEN (`tools/fb/src/docxopen.rs`) enforces that. `fb render --engine docx` refuses a package that fails it. `fb check --engine docx` runs it on every sample. `just lint` (`fb lint docx`) runs it on every committed `usage/OUTPUT-*.docx`. The check needs a valid zip and well-formed XML. Every part needs a content type and no part may be overridden twice. Every relationship target must exist, and every relationship id a part uses must be declared once in its `.rels`. Then `soffice` must convert the file. A raw `w:sectPr` in a filter must not name a reference document's footer id (`rIdFooter1`). pandoc keeps those ids in some versions and renumbers them (`rId9`) in others, and a dangling id stops the file from opening (fb-595.64). Name the footers `fb render` adds instead (`rIdFtrNone`, `rIdFtrPage`, `rIdFtrAdd`, see `docxpass.rs`), and write the last section to `$FORMBOOK_FINAL`. When a `docx/render.sh` adds a relationship or content type that pandoc already carried over, `fb render` drops the identical copy (`docxdedupe.rs`). A conflicting copy (same id, other target) is still refused.
